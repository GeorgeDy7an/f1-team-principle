# 设计思路与系统说明

## 设计目标

将复杂赛事经营压缩成可以快速推进的决策体验：玩家不用操作赛车，也不需要等待逐圈模拟；他们在阵容、研发、资源和关键比赛节点作出选择，再通过赛事结果与赛季反馈理解这些选择的影响。

## 一个赛季的节奏

完整作品以赛前准备为起点，玩家查看车手、安排阵容并选择研发投入。进入赛季后，比赛按最终结果模拟，可逐站推进或直接推进至下一个决策节点。赛季中出现少量比赛事件和一次阶段调整；当末站存在关键名次悬念时，还可能出现一次额外决策。赛季结束后展示成绩和成长反馈，进入下一年。

这个结构把“短时间浏览结果”和“需要思考的时刻”分开，力求减少连续重复操作。实际玩家反馈也表明，仅减少顶层节点并不够：每个节点内部的页面数量同样影响节奏。

## 主要系统

- **结果级比赛模拟**：比赛结果综合赛车、车手、玩家决策与随机波动生成。异常比赛使用解释标签呈现，不逐圈模拟天气、安全车或具体事故。
- **决策与资源**：赛前、季中和部分事件中的选择影响当季准备、车手培养或资源压力；单站效果与长期效果分别记录。
- **车手与车队世界**：阵容、合同、新人、车手成长和赛车发展跨赛季变化，让管理决定产生延续性。
- **成长反馈与人格**：通过能力变化、人格标签与叙事反馈，展示车手在车队中的发展；隐藏信息不会全部直接公开。
- **赛季和十年结算**：除比赛成绩外，也关注车队相对自身起点的进步和管理过程，让弱队重建与强队争冠有不同的目标。

## 技术取舍

浏览器端以 HTML、CSS 与 JavaScript 实现，不依赖逐圈赛车物理或实时操作。模拟将基础能力、选择影响和受控随机性组合，既保持可解释性，也允许偶发冷门。界面迭代重点包括手机视口内分页、固定推进操作和将复杂详情收进独立视图。

仓库中的演示是单独制作的简化示例，旨在说明“决策 → 模拟 → 反馈”的思路；其虚构数据和计算方式不代表完整作品的内部实现。

## 待改进

复杂经营信息与移动端空间存在天然张力；游戏仍需要持续关注小屏可访问性、重复事件、决策反馈清晰度和长期数值平衡。批量模拟能帮助发现统计异常，但不能替代真实设备与玩家体验测试。
